## 三、启动 / 停止

### 3.1 日常使用（双击即可）

- 启动：双击 `后端/skin-backend/启动后端.cmd`（前台运行，关闭窗口即停止）
- 停止：双击 `后端/skin-backend/停止后端.cmd`

启动脚本会自动完成：探测 JDK 21+（优先 21）→ 探测 Maven → jar 缺失或源码比 jar 新时自动 `mvn package` → 检查端口 → 启动并等待健康检查通过。密钥不可解密等非致命问题只告警，不阻断启动。

### 3.2 后台运行 / 停止（推荐，与当前部署一致）

```powershell
cd "后端\skin-backend"
powershell -ExecutionPolicy Bypass -File .\start-backend.ps1 -Background   # 后台启动
powershell -ExecutionPolicy Bypass -File .\start-backend.ps1 -Stop         # 停止
```

### 3.3 其他参数

```powershell
powershell -ExecutionPolicy Bypass -File .\start-backend.ps1 -Port 5176    # 换端口
powershell -ExecutionPolicy Bypass -File .\start-backend.ps1 -RunTests    # 强制重新构建并跑测试
```

### 3.4 在新电脑上首次部署

需要 JDK 21+ 与 Maven（脚本会在 PATH、`%USERPROFILE%\.jdks`、`Program Files` 等处自动查找；本机若没有全局 Java，脚本也能找到用户目录下的 JDK）。若 `target` 下没有 jar，脚本会自动构建；构建依赖已缓存在 `%USERPROFILE%\.m2\repository`。

### 3.5 开机自启动

当前**未配置**开机自启动；电脑重启后需重新执行一次后台启动命令（见 3.2）。如需开机自启，可把该后台启动命令注册为“登录时运行”的计划任务。

## 四、接口清单与访问约束

| 接口 | 说明 |
| --- | --- |
| `GET /api/medical/status` | 后端、存储、AI 配置状态 |
| `GET/POST /api/medical/records` | 检查列表 / 新建记录 |
| `GET/PUT /api/medical/records/{id}` | 检查详情 / 保存（PUT 必须携带最新 `version`，冲突返回 409） |
| `GET /api/medical/centers/lab/records` | 检验中心记录 |
| `GET /api/medical/patients`、`/patients/{id}/reports` | 患者索引 / 患者报告 |
| `POST /api/medical/analysis` | 图片分析（multipart 字段 `image`，PNG/JPEG ≤10MB；未配置密钥时 503） |
| `GET /api/medical/media/{filename}` | 分析原图与结果图 |

访问约束（服务端强制）：

- 只允许 `127.0.0.1` / `localhost` 访问，跨站写请求返回 403；如需局域网访问，需同时修改 `server.address` 与 `LocalRequestFilter`，请先评估医疗数据安全。
- 静态资源 `no-store`，页面修改后刷新即生效。
- 上传图片最大 10MB（请求 11MB）；系统未接入独立生成式图片模型，AI 结果仅作辅助观察、需医生复核。

## 五、DeepSeek 密钥（启用 AI 图片分析）

**当前状态（2026-11-11 起）**：`aiConfigured=true`，AI 图片分析已在本机启用；密钥通过**当前 Windows 用户环境变量** `DEEPSEEK_API_KEY` 提供，启动脚本会打印“AI : 使用环境变量 DEEPSEEK_API_KEY”。

- 背景：`后端/skin-backend/.local/deepseek-key.dpapi` 是用 **Windows DPAPI** 加密的，只能由创建它的 Windows 用户/计算机解密；本机解密失败（`Key not valid for use in specified state`），因此改用环境变量方式。源码/仓库中未写入密钥。
- 查看/修改密钥：
  - 图形界面：Win+R → `sysdm.cpl` → 高级 → 环境变量 → 用户变量中编辑 `DEEPSEEK_API_KEY`；
  - 命令行：`setx DEEPSEEK_API_KEY "sk-..."`（需重新打开窗口），改完重启后端生效。
- 其他启用方式（任选其一）：
  1. 临时会话：`$env:DEEPSEEK_API_KEY="sk-..."`，再执行 `start-backend.ps1`；
  2. 新建 `后端/skin-backend/.local/deepseek-key.txt`，内容为密钥明文（该目录已在 `.gitignore` 中，仅限本机使用）。
- 默认模型 `deepseek-flash`（需支持图像输入），可用环境变量 `DEEPSEEK_MODEL` 覆盖。

## 八、常见问题

1. **端口被占用**：`端口 5175 已被占用` → 用 `-Port 5176` 换端口，或停止占用进程。
2. **启动失败**：先看 `logs/backend.out.log` / `backend.err.log`；常见原因是 JDK 版本过低（需 21+）或 Maven 不可用。
3. **页面一直“正在连接医疗数据库…”**：确认后端在运行；必须通过 `http://127.0.0.1:5175` 或 `http://localhost:5175` 访问，用机器名/IP 会被安全过滤器拒绝。
4. **历史数据**：`data/inspections.json` 中的 5 条记录含旧版联调数据（imaging/pathology/functional 等中心），前端只展示 `center=lab` 且 `type=皮肤检验` 的记录；新建记录仅支持皮肤检验。旧 H2 文件 `医疗数据库/medical.mv.db` 已不被当前后端使用。
5. **演示数据**：前端内置带“示例”标记的演示记录，仅用于展示流程，不会写入后端；正式记录需“新建检查”后保存。
