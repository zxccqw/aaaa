# 皮肤检验工作台登录接入

前端目录为 frontend，Spring Boot 源码为 backend。登录页沿用网站的简体中文和皮肤检验业务。医生的菜单仅有工作台总览和皮肤检验，管理员进入平台总览，侧边栏显示安全计算、功能演示和工作空间。Spring Boot 会话负责账号校验和接口权限，患者索引和系统状态接口仅限管理员。皮肤检验内部原有检查、影像和报告操作继续可用。

## 本地运行

使用 JDK 21 和 Maven，在 backend 目录运行 mvn clean package。启动前为 Java 进程配置下列环境变量。两类账户的密码必须不同，账号和邮箱不得跨角色重复。账号和邮箱可任选一种配置，也可同时配置。请为两类账号各自生成随机强密码。

| 环境变量 | 用途 |
| --- | --- |
| DOCTOR_USERNAME / DOCTOR_EMAIL | 医生账号 / 邮箱 |
| DOCTOR_PASSWORD | 医生密码 |
| ADMIN_USERNAME / ADMIN_EMAIL | 管理员账号 / 邮箱 |
| ADMIN_PASSWORD | 管理员密码 |
| FRONTEND_LOCATION | 前端绝对路径，格式为 file:/绝对路径/frontend/，末尾保留斜杠 |
| SKIN_STORAGE | 数据目录，部署时指向现有数据目录 |
| PORT | Spring Boot 端口，默认为 5175 |

运行 java -jar target/skin-backend-1.0.0.jar，然后打开 http://127.0.0.1:5175/。本包不含线上数据、图片或正式账号。

## 更新现有服务器

将 frontend 文件发布到现有前端目录，并将构建出的 JAR 替换到现有 Spring Boot 服务使用的位置。保留原有 SKIN_STORAGE 和 AI 服务配置。

使用 HTTPS 对外提供登录。为 Spring Boot 配置 PUBLIC_ORIGIN 为完整的公开站点来源，例如 https://skin.example.com（无尾部斜杠），并设置 SESSION_COOKIE_SECURE=true。保留 Nginx 代理给后端的 Host 值 127.0.0.1:5175，删除旧配置中覆盖 Origin 的 proxy_set_header Origin 行，让后端验证浏览器实际来源。更新站点配置后检查 Nginx 配置并重新加载，再重启 Spring Boot 服务。原包内的 Nginx 示例仍以 80 端口示范代理，正式站点需要自己的 HTTPS 证书与 443 监听配置。

发布后分别用医生和管理员登录。医生访问 #patients 会回到工作台，直接请求 /api/medical/patients 会收到 403。退出登录后请求 /api/medical/records 会收到 401。
